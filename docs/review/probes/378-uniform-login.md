## Lab fixture the probes assume

- **Accounts.** `riley` (real, Author, `riley@example.test`); `case` (real, login stored as `Casey`); on multisite, `netonly` (a network user who is not a member of the subsite under test) and `spammy` (marked spam). Nobody exists as `nobody` or `nobody@example.test`.
- **Three probe inputs** for each form: unknown username (`nobody`), unknown email (`nobody@example.test`), real account (`riley`, and `riley@example.test`) with a wrong password.
- **Baseline.** Every probe is run once with Keel inactive, so "core's behaviour" is a captured response, not a memory of one.
- **Comparison.** "Same response" means: same HTTP status, same `Location` header (if any), same `Set-Cookie` names, and a response body that is byte-identical after masking only values that vary by request on a clean core install (none are expected on `wp-login.php`; list any you had to mask in the record).
- **Mail.** A mail capture that records the recipient count per request, never the body or the key.
