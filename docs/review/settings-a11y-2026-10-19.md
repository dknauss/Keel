# Settings screens accessibility sweep — 2026-10-19

Result: one defect, fixed. Nine value controls on Network Policy had no
accessible name. Nothing else failed in the checks below.

## Lab

Disposable Studio site, WordPress 7.1.3 / PHP 8.4, SQLite, Keel symlinked from
the working branch. Checked as a single site, then converted to a multisite
network with Keel network-activated and a second site created. Only Keel was
active. Sessions were minted through WP-CLI the same way `bin/screenshots.mjs`
does it. No production site was touched.

Screens: Settings → Site Defaults (`options-general.php?page=keel`) and Network
Admin → Settings → Network Policy (`settings.php?page=keel-network`).

## Method

Headless Chromium (Playwright) with axe-core 4.11, scoped to the screen's
`.wrap`, using the WCAG 2.0/2.1 A and AA rules plus axe best practice.

- **Automated rules:** axe, at 1280px.
- **Keyboard:** pressed Tab through every control in the form. For each one,
  recorded focus order, the visible focus indicator, the accessible name and
  `aria-describedby`.
- **Structure:** heading outline, fieldset legends, inputs without a label,
  `aria-describedby` targets that do not exist, and intro width against the
  column width.
- **Reflow:** 1280px, 640px (equivalent to 200% zoom) and 390px. Checked for
  horizontal overflow and JavaScript console errors.

Not covered: a manual pass with a real screen reader (VoiceOver or NVDA), Windows
high-contrast mode, and locked-control states beyond what `tests/settings-render.php`
already pins. The right-to-left check is recorded separately in `TODO.md`
(2026-09-14).

## Findings

| Screen | Check | Result |
|---|---|---|
| Site Defaults | axe | No violations. Five selects are "incomplete" for contrast only because core's drop-down arrow is a background image. The text is core's `#2c3338` on white. |
| Site Defaults | Keyboard | 44 stops in document order. Every stop has a visible focus indicator. Every control except the role checkboxes and Save has `aria-describedby` pointing at its help text. The role checkboxes are named by the "Password Policy Exemptions" legend. |
| Site Defaults | Structure | One H1, then ten H2 groups. 30 fieldsets, all with legends. No missing describedby targets. |
| Site Defaults | Reflow | No overflow and no console errors at any width. |
| Network Policy | axe, before | **3 critical rules on 9 controls:** `select-name`, `label`, `label-title-only`. Affected: Frame Options, Core Auto-Updates, Post Revision Retention, Front-End Admin Bar, Admin Menu Width, Environment, Regular Session Length, Remember Me Length, Login Logo. |
| Network Policy | axe, after | No violations. Same contrast "incomplete" as above. |
| Network Policy | Keyboard | 85 stops (each row has a "Decide this for the whole network" checkbox before its value control). Every stop has a visible focus indicator. |
| Network Policy | Structure | 42 fieldsets, all with legends. The intro and the settings table share the 1078px column at 1280px, so the half-width intro reported earlier stays fixed (#217, guarded by `tests/network-screen-prose.php`). |
| Network Policy | Reflow | No overflow and no console errors at any width. |

## The defect

On Site Defaults, each select and number field is the only control in its
fieldset, and the shared renderer gave it an `aria-label`. On Network Policy the
same fieldset also holds the "Decide this for the whole network" checkbox. The
renderer skipped the `aria-label` there (`$site` gates in
`keel_defaults_render_control()`), so the legend named the group but nothing
named the drop-down or spin button itself. A screen reader announced "combo box"
with no name.

The fix gives these controls `aria-label` in both contexts.
`tests/settings-render.php` now asserts that every select, number and range
field rendered for the network screen has an accessible name, locked and
unlocked.

## Not changed

Checkboxes render at core's 16×16px. Their `<label>` wraps the statement text,
so the clickable area is the whole line, which meets WCAG 2.5.8's spacing
exception. Keel does not restyle core form controls.
